**One deviation from the requested test steps, not a bug.** `GET /index.html` with a valid
cookie returns `307 Location: /` rather than `200`. This is Cloudflare Workers Static Assets'
built-in `html_handling` (auto-trailing-slash) behavior on the `ASSETS` binding itself, applied
after the gate's cookie check passes, the same canonicalizing redirect the gate already relies
on for `/request.html` -> `/request` in the unauthenticated case. The worker's own test suite
(`workers/model/test/helpers.ts`, `fakeAssets`) encodes this exact 307 for `/index.html` ->
`/`, so the merged code matches its own tests and real Workers Assets behavior. `GET /` with the
cookie is the correct check and it returns `200` with `Cache-Control: private, no-store`,
`X-Robots-Tag: noindex, nofollow`, and `Referrer-Policy: no-referrer`, all present. No fix
made; noted here in case the runbook or a future smoke-test script assumes `/index.html`
returns 200 directly.
